# Spec — coexist with generated-region plugins (Waypoint)

Status: to implement. Date: 2026-11-15. Branch: `fix/generated-region-merge`.

## The bug

Caldera Sync treats any local-vs-baseline divergence as a conflict when the server has also
changed that note. The Waypoint plugin rewrites `%% Begin Waypoint %% … %% End Waypoint %%` blocks
in folder-note hubs whenever a folder's contents change. Two machines, each running Waypoint and
Caldera Sync, therefore conflict on hub notes continuously:

1. Machine A's Waypoint regenerates `Authors.md` → pushed to the server.
2. Machine B receives the upsert. Its local copy was also regenerated by its own Waypoint, with a
   different block (different entries, different timing), so `local !== baseline` and the remote
   changed → conflict.
3. `conflict-copy` writes `Authors conflict <timestamp>.md` locally, then adopts the remote.
4. The new file is a create inside `Articles/Authors/`, so Waypoint on both machines regenerates
   `Authors.md` again → back to step 1.

Measured 2026-11-15: **160 conflict copies in 44 minutes**, all index notes (`Authors`, `Homelab`,
`Projects`, every YouTube channel hub), and **134 of 134 copies verified byte-identical to their
parent outside the Waypoint block**. No human writing was ever in conflict. Waypoint is load-bearing
for the vault owner's workflow and is not going away; the sync plugin has to handle it.

## Required behaviour

### 1. New module `src/sync/generated.ts`

- `stripGenerated(content: string): string` — remove every generated region:
  `%% Begin Waypoint %%` … `%% End Waypoint %%` (non-greedy, multiline). Tolerate a bare
  `%% Waypoint %%` marker by treating everything from it to EOF as generated. Normalise CRLF before
  matching. Result compared with trailing whitespace stripped per line and the trailing newline
  ignored.
- `mergeGenerated(local: string, remote: string): string` — outside every generated region the
  **remote** text wins (it is the newer authoritative copy of hand-written content). Inside a
  generated region the result is the **union of bullet lines** from both sides: remote order first,
  then local-only lines in their local order, exact duplicates removed. Non-bullet lines inside a
  region come from the remote side, in place. If the local and remote regions are already equal the
  remote text is returned unchanged.
- `isGeneratedOnlyDifference(local: string, remote: string): boolean` —
  `stripGenerated(local) === stripGenerated(remote)`.

### 2. `applyUpsert` (`src/sync/engine.ts`)

Before the existing conflict branch: if the local file has unsynced changes **and** the difference
is generated-only, it is not a conflict.

- `merged = mergeGenerated(local, remote)`
- if `merged === remote.content` → `adoptRemote(path, remote)`
- otherwise write `merged` locally, push it with `If-Match: remote.checksum`, and baseline the
  checksum the server returns.
- **No user-facing Notice** on this path: it is expected Waypoint churn, and a notice per hub
  regeneration is exactly the noise this fixes.
- If the push is rejected (409/412) fall through to the existing conflict path once — do not loop.

### 3. `resolveConflict`

Run the same generated-only check **before** the `conflictStrategy` switch, so `conflict-copy`
never writes a copy when the only difference is a generated region. Genuine two-sided edits keep
today's behaviour exactly.

### 4. Unchanged

- Conflict copies are ordinary notes and stay in the sync.
- Filename sanitisation, echo suppression, the storm/nesting safeguards and the large-sync
  circuit-breaker stay as they are.

## Tests (must fail before the fix, pass after)

`test/generated.test.ts` (unit):
- no block → `stripGenerated` is identity, `isGeneratedOnlyDifference` false when text differs
- one block, two blocks, CRLF input, block at end of file
- merge: remote-only entry, local-only entry, both, reordering only, nested indented bullets
- merge is idempotent: `mergeGenerated(x, x) === x`

`test/engine.generated.test.ts` (integration, fake client — mirror the existing engine test harness):
- a hub whose local and remote copies differ only inside the Waypoint block produces **no** conflict
  copy and converges to the merged content
- a hub with a real edit inside the hand-written body still produces a conflict copy (regression
  guard)
- the merged result is baselined so the next event for the same path is a no-op

## Acceptance command

```
npm run build && npm test
```

Integration tests that require a live Caldera server may be skipped by their existing guard; the
two new test files must not require a live server.

## Version

Bump `manifest.json` to `0.2.1`, add `0.2.1` to `versions.json`, and note the fix in `README.md`
under a "Known plugin interactions" heading: Waypoint and similar folder-index plugins are
supported, because differences confined to their generated block are merged rather than copied.
